From terraform-github-tacos

Your workflow calls the action once in each job, with step set to the job it runs in. The apply job's environment has the same name as the workspace.

By default it applies after the merge, in HCP Terraform's order: a pull request only plans, and once it merges, the push to the default branch plans again and applies when the environment approves, or at once for a workspace in auto-apply. With apply-before-merge set to "true" on the pending, apply and merge steps, a pull request is applied first and merges once the apply succeeds.

Steps

step Job What it does
plan plan, before planning With require-up-to-date, refuses a pull request that is behind its base.
changes plan, after planning Marks the workspace as having changes to apply.
pending one job after the plans Lists the workspaces to apply, and refuses an environment that is missing, or has no required reviewers unless its workspace is in auto-apply. Cancels older runs of the same branch that still wait for approval, unless one of their jobs is running. On a pull request it lists nothing, unless apply-before-merge.
apply apply, first step Records who approved, or that nobody had to. On a push, refuses unless the commit is still the head of the branch. On a pull request, refuses unless apply-before-merge, and then refuses when the pull request moved or merged, or with require-up-to-date fell behind.
result apply, last step, with if: always() Writes what the apply changed and whether it succeeded.
gate the required check Fails unless every job it needs succeeded. The apply job may be skipped.
merge after the gate, with apply-before-merge Merges the pull request. When this run has nothing to apply, merges only if an earlier run of it was approved or applied an auto-apply workspace. Fails when the pull request has not merged 2 minutes after the apply, since production is then ahead of the default branch. Does nothing without apply-before-merge.
collapse plan, last step, with if: always() Hides, as outdated, every plan comment of dflook/tofu-plan or dflook/terraform-plan but the newest of each workspace. Comments starting with **<workspace> apply: are hidden the same way.

The apply job should make a fresh plan and apply it only when it matches the approved one, as dflook/tofu-apply does without plan_path or auto_approve. On a push, dflook's plan updates the merged pull request's plan comment with the plan of the default branch, and the apply compares against that comment.

Only the newest commit of the default branch applies, since its plan carries the changes of every commit before it that has not been applied. So the push run has to plan every workspace that has changes: a workflow that plans only the workspaces a pull request changes should plan them all on a push. A change made since the plan, such as a workflow_dispatch apply, makes the fresh plan differ and stops the apply; "Re-run all jobs" plans again. A commit pushed to the default branch without a pull request has no plan comment, so apply it with workflow_dispatch.

Auto apply

A workspace applies without an approval when its environment has no required reviewers, as with HCP Terraform's auto apply. GitHub decides whether the apply job waits, so this is set on the environment: create it without reviewers, with the module's auto_apply, and list the workspace in the pending step's auto-apply input. The list is what lets pending tell such an environment from one created by mistake, which it refuses. Every other workspace waits for its reviewers. 

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        id: pending
        with:
          step: pending
          auto-apply: dns

After the merge, an auto-apply workspace applies as soon as the push is planned, and the apply still goes ahead only when its fresh plan matches that one. With apply-before-merge it applies as soon as the pull request is planned, before anyone has reviewed it, so give auto apply only to workspaces that anyone who can push a branch may change.

Each step writes a job summary, so the run page shows what was planned, who can approve, who approved, and what the apply changed.

Permissions

step Permissions
plan pull-requests: read
pending actions: write, checks: read
apply actions: read, contents: read, pull-requests: read
merge actions: read, contents: write, deployments: read, pull-requests: write
collapse pull-requests: write

A whole workflow

This workflow has one workspace per directory, network and dns. Put it in .github/workflows/, change the workspace list and add your credentials. Make the gate job's name, tofu gate, a required status check of the default branch. 

name: tofu
on:
  pull_request:
  push:
    branches: [main]
  workflow_dispatch:
    inputs:
      workspace:
        description: The workspace to apply from this branch, once its environment approves.
        required: true
        type: choice
        options: &workspaces [network, dns]
permissions: {}
jobs:
  plan:
    name: ${{ matrix.workspace }} plan
    if: github.event_name != 'workflow_dispatch'
    strategy:
      fail-fast: false
      matrix:
        workspace: *workspaces
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: plan
          workspace: ${{ matrix.workspace }}

      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0  # v7.0.0
        with:
          persist-credentials: false

      - uses: dflook/tofu-plan@c7416238983bdd94c5486fb856bb7358f2bcc935  # v3.1.0
        id: plan
        env:
          GITHUB_TOKEN: ${{ github.token }}
        with:
          path: ${{ matrix.workspace }}

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: changes
          workspace: ${{ matrix.workspace }}
          changes: ${{ steps.plan.outputs.changes }}
          plan-json: ${{ steps.plan.outputs.json_plan_path }}
          plan-text: ${{ steps.plan.outputs.text_plan_path }}

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        if: always()
        with:
          step: collapse

  pending:
    needs: plan
    if: >-
      !cancelled() && (github.event_name == 'workflow_dispatch'
      || (github.event_name == 'push' && needs.plan.result == 'success'))
    runs-on: ubuntu-latest
    permissions:
      actions: write
      checks: read
    outputs:
      workspaces: ${{ steps.pending.outputs.workspaces }}
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        id: pending
        with:
          step: pending
          workspaces: ${{ inputs.workspace && format('["{0}"]', inputs.workspace) || '' }}

  apply:
    name: ${{ matrix.workspace }} apply
    needs: pending
    if: >-
      !cancelled() && needs.pending.result == 'success'
      && needs.pending.outputs.workspaces != '[]'
    strategy:
      fail-fast: false
      matrix:
        workspace: ${{ fromJSON(needs.pending.outputs.workspaces) }}
    runs-on: ubuntu-latest
    environment: ${{ matrix.workspace }}
    permissions:
      actions: read
      contents: read
      pull-requests: write
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        id: approver
        with:
          step: apply
          workspace: ${{ matrix.workspace }}

      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0  # v7.0.0
        with:
          persist-credentials: false

      - uses: dflook/tofu-apply@e3e5dfc8f935d4b152c767801046f63abf8a77d3  # v3.1.0
        id: apply
        env:
          GITHUB_TOKEN: ${{ github.token }}
        with:
          path: ${{ matrix.workspace }}
          auto_approve: ${{ github.event_name == 'workflow_dispatch' }}

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        if: always()
        with:
          step: result
          workspace: ${{ matrix.workspace }}
          outcome: ${{ steps.apply.outcome }}
          plan-json: ${{ steps.apply.outputs.json_plan_path }}
          plan-text: ${{ steps.apply.outputs.text_plan_path }}
          approver: ${{ steps.approver.outputs.approver }}

  # Make this the one required check
  gate:
    name: ${{ github.event_name == 'pull_request' && 'tofu gate' || 'tofu gate (pull requests only)' }}
    needs: plan
    if: always() && github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    permissions: {}
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: gate
          needs: ${{ toJSON(needs) }}

Apply-before-merge

With apply-before-merge, the pull request's own run waits for the approval, applies, and merges. The default branch then holds only what was applied, and a pull request that does not merge after its apply leaves production ahead of it, so the merge job fails. This is the order Atlantis and digger use, and it is usually called apply-before-merge.

Other names

  • Terrateam calls the two orders pre-merge and post-merge.
  • Terramate and Cloud Posse call the default order apply-after-merge, and Terramate also merge-before-apply.
  • After Atlantis, it is also called the Atlantis-style workflow, as in Spacelift's feedback board.


A pull request behind its base may be planned and applied unless require-up-to-date is "true". The plan runs on the merge commit, so a change on the base to the same workspace makes the fresh plan differ and stops the apply, and a change to another workspace does not. 

name: tofu
on:
  pull_request:
  workflow_dispatch:
    inputs:
      workspace:
        description: The workspace to apply from this branch, once its environment approves.
        required: true
        type: choice
        options: &workspaces [network, dns]
permissions: {}
jobs:
  plan:
    name: ${{ matrix.workspace }} plan
    if: github.event_name == 'pull_request'
    strategy:
      fail-fast: false
      matrix:
        workspace: *workspaces
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: plan
          workspace: ${{ matrix.workspace }}

      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0  # v7.0.0
        with:
          persist-credentials: false

      - uses: dflook/tofu-plan@c7416238983bdd94c5486fb856bb7358f2bcc935  # v3.1.0
        id: plan
        env:
          GITHUB_TOKEN: ${{ github.token }}
        with:
          path: ${{ matrix.workspace }}

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: changes
          workspace: ${{ matrix.workspace }}
          changes: ${{ steps.plan.outputs.changes }}
          plan-json: ${{ steps.plan.outputs.json_plan_path }}
          plan-text: ${{ steps.plan.outputs.text_plan_path }}

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        if: always()
        with:
          step: collapse

  pending:
    needs: plan
    if: >-
      !cancelled() && (github.event_name == 'workflow_dispatch'
      || (needs.plan.result == 'success' && github.event.pull_request.head.repo.full_name == github.repository))
    runs-on: ubuntu-latest
    permissions:
      actions: write
      checks: read
    outputs:
      workspaces: ${{ steps.pending.outputs.workspaces }}
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        id: pending
        with:
          step: pending
          apply-before-merge: "true"
          workspaces: ${{ inputs.workspace && format('["{0}"]', inputs.workspace) || '' }}

  apply:
    name: ${{ matrix.workspace }} apply
    needs: pending
    if: needs.pending.outputs.workspaces != '[]'
    strategy:
      fail-fast: false
      matrix:
        workspace: ${{ fromJSON(needs.pending.outputs.workspaces) }}
    runs-on: ubuntu-latest
    environment: ${{ matrix.workspace }}
    permissions:
      actions: read
      contents: read
      pull-requests: write
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        id: approver
        with:
          step: apply
          workspace: ${{ matrix.workspace }}
          apply-before-merge: "true"

      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0  # v7.0.0
        with:
          persist-credentials: false

      - uses: dflook/tofu-apply@e3e5dfc8f935d4b152c767801046f63abf8a77d3  # v3.1.0
        id: apply
        env:
          GITHUB_TOKEN: ${{ github.token }}
        with:
          path: ${{ matrix.workspace }}
          auto_approve: ${{ github.event_name == 'workflow_dispatch' }}

      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        if: always()
        with:
          step: result
          workspace: ${{ matrix.workspace }}
          outcome: ${{ steps.apply.outcome }}
          plan-json: ${{ steps.apply.outputs.json_plan_path }}
          plan-text: ${{ steps.apply.outputs.text_plan_path }}
          approver: ${{ steps.approver.outputs.approver }}

  # Make this the one required check
  gate:
    name: ${{ github.event_name == 'pull_request' && 'tofu gate' || 'tofu gate (pull requests only)' }}
    needs: [plan, pending, apply]
    if: always() && github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    permissions: {}
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: gate
          needs: ${{ toJSON(needs) }}

  merge:
    needs: [pending, apply, gate]
    if: >-
      !cancelled() && needs.gate.result == 'success'
      && (needs.apply.result == 'success' || needs.pending.outputs.workspaces == '[]')
    runs-on: ubuntu-latest
    permissions:
      actions: read
      contents: write
      deployments: read
      pull-requests: write
    steps:
      - uses: femiwiki/terraform-github-tacos@v0.4.0  # x-release-please-version
        with:
          step: merge
          apply-before-merge: "true"

From v0.3.0

v0.3.0 always applied before the merge. To keep that, add apply-before-merge: "true" to the pending, apply and merge steps. To apply after the merge instead, change the workflow to the first one above: add the push trigger, plan on pushes too, run pending on pushes and workflow_dispatch only, make the gate need only the plan jobs, and drop the merge job.
